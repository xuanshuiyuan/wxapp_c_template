# 评审流程（唯一真源）

## 角色

- **代码窗口**：实现变更、跑验证、提交、发起评审。
- **评审窗口**：用户为本轮新开的独立会话；只读、只出报告、不改代码。

## 范围

`<base>` = `.claude/project-meta/.last-sync` 的 hash；`<head>` = 当前 HEAD。
评审前代码窗口必须已提交；未提交改动不在范围内（用户特别要求时另说）。

## 报告

- 路径：`.claude/project-meta/versions/vN/review.md`；复评 `review-r2.md`、`review-r3.md`…
- 分级：**阻断（P0）/ 建议（P1 / P2）**；每条给 `文件:行号`、问题、触发场景、最小修法。
- 每条标 **`代码级`**（可直接改）或 **`需用户定`**（口径/产品决策）。
- 架构单独给「可接受 / 需调整」判断。

## 交互

- 评审窗口**不直接问用户**；所有条目一次性 `SendMessage` 发回代码窗口。
- 代码窗口只问用户三件事：① 是否开始评审；② 修复后是否复评；③ 需要用户定的条目。
- 通过（无阻断）→ 回发「评审通过（review.md）」。
- 不修的条目在复评请求里列明「未修 + 原因」。

## 收尾

- 评审结论回填 `versions/vN/CHANGELOG.md` 的「评审」小节。
- 收尾把 `git rev-parse HEAD` 写入 `.claude/project-meta/.last-sync`。
