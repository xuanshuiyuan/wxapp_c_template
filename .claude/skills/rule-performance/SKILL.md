# rule-performance

> 原 `.claude/rules/performance.md` 全量迁入本文件，**本文件是唯一权威**。

## 硬性禁令

- ❌ 禁止一次性加载大量数据到前端（必须分页；几千条用 `u-list` / `u-virtual-list`，见 `rule-ui-components`）
- ❌ 禁止在循环中发起网络请求（能合并接口就合并，不能合并改并发 `Promise.all` 并控制批次）
- ❌ 禁止频繁触发重渲染（模板里调方法、逐字段改 reactive 大对象都算）
- ❌ 禁止无索引的全表扫描（后端预留）
- ❌ 禁止在日志中打印大对象（与 `rule-security` 的日志脱敏同条：本项目 `console.*` 还受 `rule-coding-basics` §9 禁令约束）

## 1. 通用原则

- 避免不必要的计算和重复请求；用缓存减少重复工作。
- 异步操作注意超时和错误处理；大数据量场景分页/虚拟列表。

## 2. 前端（uni-app）

- **渲染**：列表分页或虚拟滚动（`useList` 已封装触底加载，见 `rule-add-page`）；复杂计算用 `computed` 缓存；避免模板中调方法；`v-if`/`v-show` 按重渲染代价选。
- **网络**：合并请求减少 HTTP 次数；图片懒加载与压缩（`u-image` 自带兜底）；合理本地缓存（`services/storage.js`）；避免重复请求同一数据。
- **启动体积**：控制首页包体积；非首屏页面进分包（`packages/`，方向禁令见 `rule-project-structure`）；延迟加载非关键资源。
- **小程序特定**：避免频繁 `setData`（大对象整改 → 拆细粒度 `ref`）；减少 WXML 节点数（四态手写已被 `app-list-state` 收敛）；图片走 CDN 与合适尺寸（域名由 `.env` 的 `VITE_OSS_HOST` 提供；代码里只写 OSS 相对路径、经 `utils/oss.js` 的 `ossUrl()` 拼域名，**禁止在页面写死图片全地址**——否则生产指错 CDN）。

### 2.1 同一份数据的重复请求：去重三件套（照抄这两处现成实现）

「按 key 轮询」和「按事件刷新」这两类最容易写出连点打爆后端。模板自带的基础设施先例：`services/location.js`（缓存 + 失败退避 + 单飞）。按 key 取数需自建 composable 时，三件事各管一段，**缺一就有真实事故**：

| 手段 | 怎么做 | 治什么 |
|---|---|---|
| **① 新鲜期窗口（SWR）** | 缓存条目带 `at` 时间戳；`Date.now() - at < interval` 视为新鲜 → **直接吃缓存不发请求**；陈旧则「先吃缓存渲染 + 后台静默重拉」（滑动零等待） | 高频切 tab / 反复进页把同一个接口打爆 |
| **② 同 key 单飞** | `inflight[key]` 存进行中的 Promise，同 key 再来直接 `return` 它；`finally` 里删。**普通对象即可，无渲染语义的东西不要塞进 `ref`**（否则每次请求都触发重渲染） | 快速连滑/连点时每辆车各发一次；**付费接口（查车型/估价/OCR）尤其致命** |
| **③ 规范 key（canonicalKey）** | 首屏「不带参数」（后端默认取最新绑定车）请求回来后，**用响应里的真实 id 把缓存与当前 key 归一**，此后轮询/下拉都带它 | 后台刷新把用户正在看的车跳回「最新绑定」；缓存挂在两个 key 上白白翻倍 |

配套口径（都是定稿，别再自创）：

- **新鲜期长度对齐后端频控**：本地窗口不要短于后端缓存 / 频控窗口——窗口内重拉拿到的也是同一份数，只会白烧频控额度（撞 40205）。
- **常驻定时器能省就省**：不做秒级 ticker 自己算「x 秒前刷新」，刷新文案吃接口给的值（`realtime.refresh_text`），接口未返时兜底固定串。轮询 `onShow` 起、`onHide` 停。
- **装饰性数据失败静默**：非主干展示位恒 `{ toast: false }`，**失败保上一次旧值**、字段残缺也不覆盖旧值，更不参与页面错误态判定（宁可显示旧数据也不闪空、不弹错）。
- **会话级缓存的适用面**：结果不随页面变化、且取一次代价高的东西（定位坐标）缓在 `services/` 模块作用域；有渲染语义的状态才进 `store/`。
- **并发而非串行**：互不依赖的取数一起发（`Promise.all`），指示器等到**全部结算**再收。

**2.1.1 从子页返回列表：不要无条件重拉（2026-11-12 用户真机反馈「返回列表时闪一下」）**

列表页在 `onShow` 里无条件 `reload` 时，从详情页返回哪怕什么都没改也会整表替换：`setData` 重绘 + 底部「没有更多了」先消失再出现 = 肉眼可见的闪。定稿做法：

| 场景 | 判据 | 现成实现 |
|---|---|---|
| 单一列表消费 | **一次性 dirty 标记**：子页真的改了数据才 `mark`，列表 `onShow` 用 `take` 消费一次 | 模板的 demo 首页是「onShow 无条件重拉」；数据量大时再建 `store/<域>.js` 的 `mark/take` |
| 一份数据被多页消费 | **单调修订号**：改动时 `+1`，每页各记自己上次看到的号，不等即重拉 | 需要时在 `store/<域>.js` 实现 `bumpRevision / currentRevision` |

口径：① 首次 `onShow` 紧跟 `onLoad`，要挡掉（首次进入取到的就是最新数据）；② 打标记的位置必须在**真正改了数据的成功回调**里（删除成功 / 解绑成功 / 改价成功 / 加车成功），失败路径不打；③ **一次性 dirty 不能给多页共用**——先出现的那页会把它吃掉，后一页就永远吃不到更新。

## 3. 后端（跨模块/未来后端预留）

- **数据库**：查询走索引；避免 N+1；大结果集分页；合理使用 Redis/Memcached。
- **接口**：响应时间控制在合理范围；慢接口异步化；高并发考虑限流/降级。
- **资源**：防内存泄漏；及时释放连接与文件句柄；使用连接池。
