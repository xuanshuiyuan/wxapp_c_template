# rule-security

> 原 `.claude/rules/security.md` 全量迁入本文件，**本文件是唯一权威**。前端特有约定（存储走 `services/storage`、请求走 `curl`、登录只调 `session`）见 `rule-auth-state` / `rule-api-request`。

## 硬性禁令

- ❌ 禁止硬编码密钥/密码/AppID/token（含提交进 git 的任何文件）
- ❌ 禁止信任前端传来的用户身份做敏感判断（身份必须服务端认定）
- ❌ 禁止用字符串拼接 SQL
- ❌ 禁止在日志中输出敏感信息（含大对象间接泄露）
- ❌ 禁止前端执行签名/支付核心逻辑
- ❌ 禁止前端直接渲染用户输入到 HTML（`v-html` / `innerHTML`）
- ❌ 禁止本地存储中存放密码；token 必须设合理过期时间；登出必须清除本地登录态

## 1. 通用原则

- **输入校验**：所有用户输入必须校验；校验逻辑优先在服务端执行；前端校验只提升体验。
- **输出编码**：渲染用户输入必须转义；用框架提供的安全渲染方式，不手拼 DOM。
- **敏感信息**：敏感配置走配置文件或环境变量（本项目：`config/env.js`、`config/app.js`，且不得写入真实密钥）。

## 2. 前端安全（uni-app）

- XSS：禁止 `v-html` 渲染用户输入；禁止直接操作 `innerHTML`；用户输入渲染前转义。
- 本地存储：token 只经 `services/storage.js`（统一前缀），登出走 `session.logout()`（会清登录字段）。
- 接口安全：所有 HTTP 走 `curl` 封装（签名在 `services/http/sign.js`）；签名逻辑必须在服务端执行的场景不得搬到前端。

## 3. 后端安全（跨模块/未来后端预留）

- SQL 注入：参数化查询；ORM 动态条件注意转义。
- 认证授权：敏感接口必须鉴权；权限在服务端校验；禁止依赖前端传来的 user_id 做安全边界（本项目 `rule-project-structure` 同此一条）。
- 文件上传：限制类型与大小；禁止执行用户上传的文件；存储路径不可预测。
- 加密：密码加盐哈希（bcrypt 等）；通信 HTTPS；随机数用加密安全随机数。

## 4. 支付 / 消息业务安全

- 签名验证在服务端；金额用 decimal 避免浮点误差；回调必须幂等；敏感通知内容脱敏。
